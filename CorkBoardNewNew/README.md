# CorkBoard — скелет проекта

## Как запустить

Это набор `.swift`-файлов, не готовый `.xcodeproj` (его нельзя собрать здесь,
в Linux-контейнере). Чтобы запустить:

1. Открой Xcode → **File → New → Project → macOS → App**.
2. Interface: **SwiftUI**, Language: **Swift**, назови проект `CorkBoard`.
3. Удали автосгенерированные `ContentView.swift` и `<Name>App.swift`.
4. Перетащи все файлы из `Sources/CorkBoard/` в проект (Copy items if needed ✅).
5. Собери и запусти (⌘R).

Первый рабочий сценарий: «Добавить фото…» → фото раскладываются как
полароиды со случайным углом → «Экспортировать как обои» — картинка
рендерится под каждый подключённый монитор и ставится через
`NSWorkspace.setDesktopImageURL`.

## Архитектура (почему так)

```
Board / BoardItem        ← модель данных (Codable, общая для А и Б)
        │
BoardRenderer             ← рисует Board в любой CGContext
  ├─ ItemFrameRenderer     ← polaroid / stamp / sticker — стиль рамки
  └─ LayoutEngine          ← авто-расстановка без наложений
        │
        ├── WallpaperExporter   ← Вариант А: рендер в PNG → setDesktopImageURL
        └── (BoardOverlayWindow) ← Вариант Б: тот же BoardRenderer, но в
                                    прозрачном NSWindow поверх рабочего стола
```

Ключевая идея: **всё, что рисует контент, не знает, куда оно рисует**
(экспорт в файл или live-окно). Поэтому переход к Варианту Б — это
замена только `WallpaperExporter`, а не переписывание рендера.

## Roadmap

### Этап 0 — Каркас (сделано в этом скелете)
- [x] Модель `Board` / `BoardItem`, Codable
- [x] `BoardRenderer` + протокол `ItemFrameRenderer`
- [x] `PolaroidRenderer` (базовая версия)
- [x] `LayoutEngine` — рандомная раскладка без пересечений
- [x] `WallpaperExporter` — экспорт под каждый экран
- [x] Минимальный SwiftUI-редактор (добавить фото, превью, экспорт)

### Этап 1 — Довести Вариант А до приятного MVP
- [ ] Настоящая текстура пробки (файл-ассет + `CGPattern`/tile вместо заливки)
- [ ] `StampRenderer` — зубчатый край через `CGPath` (перфорация)
- [ ] `StickerRenderer` — вырезание по альфа-каналу (die-cut), не просто bbox
- [ ] Рисование пинов: кнопка / скрепка / скотч — векторные фигуры в `drawPin`
- [ ] Drag-переупорядочивание фото в списке (z-index) в самом редакторе
- [ ] Сохранение/загрузка `Board` в JSON (уже Codable — просто добавить persist)
- [ ] Поддержка нескольких мониторов с разным разрешением/соотношением сторон
- [ ] Обработка ошибок и edge cases (нет фото, повреждённый файл и т.п.)

### Этап 2 — Полировка и распространение
- [ ] Иконка приложения, простое меню (About, Preferences)
- [ ] Notarization + подпись для распространения вне App Store
  (сэндбокс App Store сильно ограничит работу с Desktop/обоями)
- [ ] Пресеты композиций ("много марок", "минимализм", "фотолента")
- [ ] Экспорт истории версий доски (галерея прошлых обоев)

### Этап 3 — Переход к Варианту Б (живая доска)
- [ ] `BoardOverlayWindow`: `NSWindow` без title bar, `.level` между
      рабочим столом и иконками Finder, `ignoresMouseEvents` там, где
      клики не нужны
- [ ] Синхронизация оверлея с каждым `NSScreen` + обработка
      `NSApplication.didChangeScreenParametersNotification`
- [ ] Поддержка Spaces (`NSWindow.collectionBehavior = .canJoinAllSpaces`)
- [ ] Drag&Drop файлов из Finder прямо на "доску"
- [ ] Перетаскивание/поворот элементов мышью поверх рабочего стола
- [ ] Персистентность состояния между запусками/перезагрузками системы
- [ ] Запуск при логине (Login Item)

## Известные технические риски
- App Store sandbox **не даст** взаимодействовать с рабочим столом на
  уровне окна — Вариант Б почти наверняка потребует распространения
  вне Mac App Store (notarized `.app`, обычная загрузка с сайта).
- Смена системной темы (light/dark) может требовать перегенерации
  текстуры/теней для консистентного вида.
- Multi-display setups с разным DPI/масштабом — тестировать отдельно.
